## 1. บทนำและวัตถุประสงค์ของต้นแบบ (Introduction & Prototype Scope)

### 1.1 ความเป็นมาของไฟล์ต้นแบบ
ไฟล์ **`Plumber_ver-1003-gu-tam-kon-dew-i-sus.rp`** (ขนาด 3.2 MB) เป็นไฟล์ต้นแบบเชิงโต้ตอบความละเอียดสูง (High-Fidelity Interactive Prototype) ที่สร้างขึ้นด้วยโปรแกรม Axure RP 10 โดยได้รับการพัฒนาและต่อยอดมาจากรุ่น `Plumber_v4.rp` เพื่อใช้เป็น **แม่แบบพิมพ์เขียว (Blueprint)** ในการออกแบบสถาปัตยกรรมหน้าจอ ประสบการณ์ผู้ใช้ (UX) และส่วนติดต่อผู้ใช้ (UI) ก่อนการเขียนโค้ดระบบจริง

### 1.2 วัตถุประสงค์ของต้นแบบ
1. **การตรวจสอบความต้องการ (Requirements Validation):** ตรวจสอบกับคณะกรรมการกองทุนประปาหมู่บ้านวังยางว่าฟอร์ม ป.17, ป.31/32, กค.4 และฎีกา 10% มีหน้าตาและจุดกรอกข้อมูลตรงตามระเบียบทางราชการหรือไม่
2. **การทดสอบความลื่นไหลของผู้ใช้ (Usability & Flow Testing):** ทดสอบการกดสลับหน้าจอ การค้นหาด้วยเบอร์โทรศัพท์ และการเปิดหน้าต่างพรีวิวใบเสร็จโดยไม่ให้หน้าจอกระตุก
3. **การเป็นเกณฑ์อ้างอิงในการเขียนโค้ด (Design-to-Code Specification):** ช่วยให้นักพัฒนาสร้างคอมโพเนนต์ CSS และโครงสร้าง HTML ได้ตรงตามตำแหน่งและสีสันที่ออกแบบไว้ 100%

## 2. วิธีการเปิดและเรียกดูต้นแบบ (How to Run & Preview the Prototype)

### 2.1 การเปิดผ่านโปรแกรม Axure RP 10
1. ติดตั้งโปรแกรม **Axure RP 10** บนคอมพิวเตอร์ (ตัวติดตั้ง `AxureRP-Setup.exe` อยู่ในโฟลเดอร์ Downloads)
2. ดับเบิลคลิกเปิดไฟล์ `Plumber_ver-1003-gu-tam-kon-dew-i-sus.rp`
3. ในแผงด้านซ้ายมือ (Pages Panel) จะปรากฏผังโครงสร้างหน้าจอทั้งหมดของระบบประปาหมู่บ้าน

### 2.2 การพรีวิวแบบ Interactive บนเว็บบราวเซอร์ (Local Preview)
1. ในหน้าต่างโปรแกรม Axure RP ให้กดปุ่ม **[Preview]** ที่มุมบนขวา หรือกดแป้นลัด **`F5`** บนคีย์บอร์ด
2. โปรแกรมจะทำการแปลงวิดเจ็ตและ Dynamic Logic ออกมาเป็นหน้าเว็บจำลองบน Google Chrome หรือ Microsoft Edge ทันที
3. ผู้ใช้งานสามารถคลิกปุ่ม พิมพ์ข้อความในช่องค้นหา และสลับแท็บงานได้เหมือนกำลังใช้งานเว็บจริง

### 2.3 การส่งออกเป็นเว็บจำลอง HTML (Publish to HTML Files)
หากต้องการนำต้นแบบไปเปิดบนคอมพิวเตอร์ที่ไม่มีโปรแกรม Axure:
1. ไปที่เมนู **Publish &rarr; Generate HTML Files...** (หรือกด `Ctrl + F5`)
2. เลือกโฟลเดอร์ปลายทางที่ต้องการบันทึก แล้วกด **Generate**
3. โปรแกรมจะสร้างชุดไฟล์ HTML/JS/CSS ออกมา ให้ดับเบิลคลิกไฟล์ `start.html` หรือ `index.html` เพื่อเปิดทดสอบบนเบราว์เซอร์ใดก็ได้

## 4. ขั้นตอนการทดสอบและสาธิตแบบ Interactive (Step-by-Step Interactive Flows)

### Flow 1: การค้นหายอดค่าน้ำประชาชนและการเปิด QR พร้อมเพย์ (Screen 1)
1. เปิดหน้าแรก **Screen 1 (Home Search)**
2. คลิกที่ช่องค้นหา `[เบอร์โทรศัพท์/บ้านเลขที่]` จะมีค่าตัวอย่าง `0812345678` ให้กด
3. กดปุ่ม **[ค้นหาค่าน้ำ]**:
   - ระบบจะสลับ State แสดงการ์ดผลลัพธ์ของผู้ใช้น้ำ นายวิชัย ใจดี (บ้านเลขที่ 123/1 โซน 1)
   - แสดงยอดเงินค่าน้ำสุทธิ **115.00 บาท**
4. คลิกที่ปุ่ม **[📱 ชำระเงินด้วย QR Code พร้อมเพย์]**:
   - หน้าต่าง Modal จะป๊อปอัปขึ้นมาตรงกลางหน้าจอ แสดงภาพ QR Code พร้อมเพย์ พร้อมข้อความระบุยอด 115.00 บาท และปุ่ม [ปิดหน้าต่าง]

---

### Flow 2: การเดินจดมิเตอร์ภาคสนาม ป.17 และตรวจจับความผิดปกติ (Screen 5)
1. เปิดหน้า **Screen 5 (Meter Reading - Form P.17)**
2. สังเกตแถบด้านบน: แสดงงวดเดือน `สิงหาคม 2567 (8-2567)` และแถบ Progress Bar ความคืบหน้าการจด `88%`
3. ในตารางรายชื่อ จะแสดงข้อมูลเรียงตามลำดับเสาบ้านจริง:
   - แถวที่ 1: รหัส `WY-001` นายวิชัย ใจดี | เลขเดิม `120` | ช่องเลขครั้งนี้กรอก `135` | หน่วยใช้ `15` | ยอดเงิน `115.00` | สถานะ `จดแล้ว`
4. **ทดสอบ Interactive Event:**
   - คลิกที่ปุ่ม **[📷 สแกน QR Code]**: จะมีป๊อปอัปกล้องจำลองพร้อมกรอบสีเขียวแสดงการสแกนสำเร็จ
   - คลิกจำลองกรอกตัวเลขน้อยกว่าเดิม (เช่น กรอก `110`): ระบบจะแสดงเส้นขอบสีแดงพร้อมข้อความ *"คำเตือน: เลขมิเตอร์ลดลงผิดปกติ"*

---

### Flow 3: การตัดรับชำระเงินและเปิดพรีวิวใบเสร็จ ป.31/32 (Screen 7)
1. เปิดหน้า **Screen 7 (Finance & Receipt Dashboard)**
2. ในแท็บที่ 1 **"รายการตัดรับชำระเงิน"**:
   - แถวผู้ใช้น้ำที่ค้างชำระจะมีปุ่มสีเขียว **[✅ รับชำระ]**
   - เมื่อคลิกปุ่ม: ป้ายสถานะจะสลับเป็น **PAID (ชำระแล้ว)** สีเขียวทันที และมี Toast แจ้งเตือนขึ้นที่มุมขวาบน
3. คลิกปุ่ม **[🧾 ใบเสร็จ]**:
   - หน้าต่าง **Quick Receipt Modal** จะเด้งขึ้นมาแบบ Lightbox
   - แสดงแบบฟอร์มใบเสร็จรับเงินมาตรฐาน ป.31/32 ขนาดครึ่งหน้า A4
   - ระบุยอดเงินตัวเลข `115.00` และแปลงตัวอักษรไทย *"หนึ่งร้อยสิบห้าบาทถ้วน"*
   - มีปุ่ม **[🖨️ พิมพ์ใบเสร็จ]** และปุ่ม **[🖥️ เปิดหน้าต่างเต็ม]**

---

### Flow 4: การติดตามหนี้ กค.4 และหนังสือเตือน 7 วัน (Screen 7 - State 3)
1. ในหน้า Screen 7 ให้คลิกที่แท็บ **"3. ทะเบียนคุมหนี้ค้างชำระ (กค.4)"**
2. คลิกเลือกตัวกรอง:
   - ปุ่ม `[ค้าง 1 เดือน]` &rarr; แสดงลูกหนี้ที่ต้องเตือนรอบแรก
   - ปุ่ม `[ค้าง 3 เดือนขึ้นไป]` &rarr; แสดงลูกหนี้เร่งด่วนขั้นวิกฤต
3. คลิกปุ่ม **[✉️ ออกหนังสือเตือน]**:
   - จะเปิดหน้าต่างจำลอง **"หนังสือเตือนระงับการจ่ายน้ำชั่วคราว"** ดึงยอดหนี้สะสม 3 เดือนรวม 450 บาท และกำหนดเส้นตายชำระภายใน 7 วัน
4. คลิกปุ่ม **[💳 ตัดชำระ]**:
   - หน้าระบบจะสลับกลับไปยังแท็บ 1 และเลือกรายชื่อลูกหนี้คนนั้นลงในช่องค้นหาให้ทันที 1 คลิก

---

### Flow 5: การซิงค์และออกฎีกาเบิกจ่ายค่าตอบแทน 10% (Screen 9)
1. ในหน้า Screen 9 ให้คลิกแท็บ **"4. ฎีกาเบิกจ่ายเงิน (10% & ค่าใช้จ่าย)"**
2. ด้านบนจะแสดงการ์ดสรุปยอดเงินสดที่เก็บได้จริง: `ยอดรับชำระแล้ว: 1,078.00 ฿`
3. คลิกปุ่ม **[🔄 ซิงค์ค่าตอบแทน 10%]**:
   - ระบบจำลองจะคำนวณ `1,078.00 x 10% = 107.80 บาท`
   - สร้างแถวฎีกาเบิกจ่ายใหม่ขึ้นมาในตารางทันที ระบุผู้รับเงิน *"นายสมบูรณ์ มั่นคง (ผู้จัดเก็บค่าน้ำ)"*
4. คลิกปุ่ม **[👁️ ดูฎีกาเบิกจ่าย]**:
   - แสดงฟอร์มใบสำคัญรับเงิน/ฎีกาเบิกจ่ายกองทุน พร้อมจุดลงนาม 3 ตำแหน่ง: ผู้รับเงิน, เหรัญญิก, และประธานกองทุน

---

### Flow 6: การดูรายงานงบดุลประจำเดือนและการลงนาม 3 ฝ่าย (Screen 18)
1. เปิดหน้า **Screen 18 (Monthly Financial Summary / Balance Sheet)**
2. หน้าจอแสดงตารางงบดุล 2 ฝั่งมาตรฐาน:
   - ฝั่งซ้ายสีเขียว: **รายรับของกองทุน** (ค่าน้ำประปา, ค่าบำรุงรักษา, ค่าติดตั้งใหม่)
   - ฝั่งขวาสีแดง: **รายจ่ายของกองทุน** (ค่าไฟปั๊มน้ำ, ค่าซ่อมท่อ, ค่าสารส้ม, ค่าตอบแทน 10%)
   - สรุปยอดคงเหลือสุทธิยกไปงวดหน้า
3. ด้านล่างแสดงจุดลงนามลายมือชื่อคณะกรรมการบริหาร 3 ท่านครบถ้วนตามระเบียบ

### Flow 7: การพิมพ์ชุดสติกเกอร์ QR Code ติดมิเตอร์น้ำ (Screen 30)

2. คลิกเลือกรูปแบบสติกเกอร์: `[ขนาดกะทัดรัด 24 ดวง]` หรือ `[ขนาดมาตรฐาน 12 ดวง]`
3. หน้าจอจะจัดเรียงแผ่นสติกเกอร์ QR Code ประจำตัวมิเตอร์พร้อมบ้านเลขที่และรหัส `WY-xxx` พร้อมจำลองการกดคำสั่งพิมพ์ (Print Dialog)

## 5. เบื้องหลังเทคนิคการโต้ตอบเชิงตรรกะใน Axure (Axure Dynamic Logic & Variables)

### 5.1 การจัดการ Dynamic Panels สำหรับแท็บงานและการสลับ State
ในหน้า `finance_billing.php` (Screen 7) มีการใช้ **Dynamic Panel** ชื่อ `DP_FinanceTabs` ที่มี 4 States:
- `State_Collection`: แท็บตัดรับชำระเงิน
- `State_Receipt`: แท็บพรีวิวใบเสร็จ ป.31/32
- `State_Arrears`: แท็บทะเบียนหนี้ กค.4
- `State_Vouchers`: แท็บฎีกาเบิกจ่าย 10%  
*เมื่อคลิกปุ่มแท็บใด จะมีคำสั่ง `Set Panel State DP_FinanceTabs to [StateName] with Slide Left/Right 200ms` ทำให้การเปลี่ยนหน้าจอลื่นไหลเหมือน Single Page Application (SPA)*

### 5.2 การใช้ Global Variables ในการส่งผ่านค่ายอดเงิน
ต้นแบบมีการประกาศตัวแปรส่วนกลาง (Global Variables) เช่น:
- `Var_SearchPhone`: เก็บเบอร์โทรศัพท์ที่ผู้ใช้พิมพ์ค้นหา
- `Var_TotalBill`: เก็บยอดเงินค่าน้ำที่คำนวณได้ (เช่น `115.00`)
- `Var_PaidStatus`: เก็บสถานะการชำระเงิน (`UNPAID` $\rightarrow$ `PAID`)  
*เมื่อผู้ใช้กดปุ่ม [รับชำระ] ในแท็บ 1 ระบบจะตั้งค่า `Var_PaidStatus = 'PAID'` และส่งผลให้ไอคอนสถานะในแท็บ 3 (คุมหนี้) อัปเดตหายไปจากรายการลูกหนี้โดยอัตโนมัติ*

### 5.3 การสร้างหน้าต่าง Modal Popup แบบ Lightbox
หน้าต่างพรีวิวใบเสร็จและ QR PromptPay ถูกสร้างเป็น Dynamic Panel ที่ตั้งค่าเริ่มต้นเป็น `Hidden`  
เมื่อผู้ใช้คลิกปุ่ม Action จะเกิด Event:  
`Show DP_ReceiptModal as Lightbox (Background: #000000 with 50% Opacity, Animation: Fade In 150ms)`  
ทำให้เกิดประสบการณ์ผู้ใช้ที่ดูเป็นมืออาชีพและตรงตามหลักการ UX สากล
