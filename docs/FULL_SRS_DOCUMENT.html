บทคัดย่อโครงงาน (Project Abstract)

โครงงานนี้จัดทำขึ้นเพื่อพัฒนาระบบสารสนเทศสำหรับบริหารจัดการกิจการประปาหมู่บ้านชนบท ทดแทนการบันทึกด้วยสมุดกระดาษแบบดั้งเดิม ระบบถูกออกแบบและพัฒนาให้รองรับการทำงานของเจ้าหน้าที่ประปาและอำนวยความสะดวกแก่ประชาชนผู้ใช้น้ำจำนวน 400 ครัวเรือน ครอบคลุมฟังก์ชันการเดินจดบันทึกมาตรวัดน้ำภาคสนามตามลำดับเส้นทางจริง (แบบ ป.17) การออกใบแจ้งหนี้และใบเสร็จรับเงิน (แบบ ป.31/32) การสร้างภาพ QR Code ชำระเงินผ่านพร้อมเพย์ตามยอดเงินจริง การควบคุมบัญชีลูกหนี้ค้างชำระ (แบบ กค.4) การคำนวณและจัดทำใบสำคัญเบิกจ่ายค่าตอบแทนผู้จัดเก็บร้อยละ 10 และรายงานสรุปงบดุลประจำเดือน

1. บทนำและประวัติการพัฒนา (Introduction & Background)
1.1 ประวัติการแก้ไขเอกสาร (Document Revision History)
เวอร์ชัน วันที่ ผู้รับผิดชอบ / คณะทำงาน สาระสำคัญของการปรับปรุง
0.1 23 ก.ค. 2567 คณะผู้จัดทำโครงงาน รวบรวมความต้องการเบื้องต้นและยกร่างโครงสร้างฐานข้อมูลเริ่มต้น
0.5 30 ก.ย. 2567 ผู้ออกแบบส่วนติดต่อผู้ใช้ จัดทำต้นแบบหน้าจอจำลองรุ่นแรกบนโปรแกรม Axure RP
0.9 3 ต.ค. 2567 นักวิเคราะห์และพัฒนาระบบ จัดทำต้นแบบฉบับสมบูรณ์ 31 หน้าจอ (Plumber_ver-1003...rp)
1.0 9 ต.ค. 2567 คณะผู้จัดทำโครงงาน จัดทำเอกสาร Full SRS ฉบับสมบูรณ์ บูรณาการร่วมกับระบบจริงบน XAMPP
1.2 วัตถุประสงค์ของโครงงาน (Project Objectives)

1. เพื่อพัฒนาระบบบันทึกการอ่านมาตรวัดน้ำภาคสนามผ่านสมาร์ตโฟน ช่วยลดความผิดพลาดในการจดบันทึกตัวเลขและป้องกันปัญหาเลขอ่านถอยหลัง
2. เพื่อพัฒนาระบบการออกใบแจ้งหนี้และใบเสร็จรับเงินที่ได้มาตรฐาน พร้อมสร้าง QR Code ชำระเงินผ่านระบบพร้อมเพย์ อำนวยความสะดวกแก่ประชาชน
3. เพื่อพัฒนาระบบติดตามลูกหนี้ค้างชำระ (แบบ กค.4) และพิมพ์หนังสือแจ้งเตือนระงับการใช้น้ำได้อย่างเป็นรูปธรรม
4. เพื่อสร้างระบบการคำนวณและจัดทำใบสำคัญเบิกจ่ายค่าตอบแทนผู้จัดเก็บร้อยละ 10 ตามมติที่ประชุมกองทุน พร้อมทั้งสรุปงบดุลประจำเดือนที่โปร่งใส ตรวจสอบได้

1.3 นิยามศัพท์และคำย่อที่ใช้ในเอกสาร (Definitions & Acronyms)
คำศัพท์ / คำย่อ ความหมายตามระเบียบปฏิบัติและทางเทคนิค
แบบ ป.17 ทะเบียนคุมผู้ใช้น้ำและการจดบันทึกเลขอ่านมาตรวัดน้ำประจำเดือน ตามระเบียบปฏิบัติงานประปาหมู่บ้าน
แบบ ป.31/32 ใบแจ้งหนี้ค่าน้ำประปา (ป.31) และใบเสร็จรับเงินค่าน้ำประปาประจำงวด (ป.32) ซึ่งเป็นเอกสารสำคัญทางการเงิน
แบบ กค.4 ทะเบียนคุมลูกหนี้ค้างชำระเงินค่าน้ำประปา จัดกลุ่มตามอายุหนี้ (1 เดือน, 2 เดือน, 3 เดือนขึ้นไป)
ค่าตอบแทน 10% เงินค่าตอบแทนผู้จัดเก็บค่าน้ำประปาในอัตราร้อยละ 10 ของยอดเงินที่รับชำระจริงในงวดนั้นๆ ตามมติที่ประชุมกองทุน
NRW (น้ำสูญเสีย) Non-Revenue Water: ปริมาณน้ำที่สูบผลิตจ่ายเข้าระบบ แต่ไม่สามารถเรียกเก็บเงินได้จากจุดรั่วซึมหรือท่อแตก
RBAC Role-Based Access Control: การกำหนดสิทธิ์การเข้าถึงข้อมูลและการทำงานของระบบตามหน้าที่ 4 ระดับ

ผู้ดูแลระบบ
(Superadmin)		 ประธานกรรมการบริหารประปา / ผู้ใหญ่บ้าน เข้าถึงระบบได้ทุกส่วน อนุมัติใบสำคัญเบิกจ่าย กำหนดอัตราค่าน้ำ ดูรายงานงบดุล และสำรองฐานข้อมูล dashboard.php
เจ้าหน้าที่
(Staff)		 เหรัญญิกกองทุน / ช่างจดบันทึกมาตรวัดน้ำ จดบันทึกเลขอ่านมาตรวัดน้ำ (ป.17) บันทึกการรับชำระเงิน ออกใบเสร็จ (ป.31/32) และคุมหนี้ (กค.4) meter_reading.php
สมาชิกผู้ใช้น้ำ
(Member)		 ชาวบ้านผู้ใช้น้ำที่ลงทะเบียน ตรวจสอบประวัติการใช้น้ำย้อนหลัง ดูยอดค้างชำระ สแกน QR Code พร้อมเพย์ และแจ้งเหตุน้ำรั่ว portal_citizen.php
ประชาชนทั่วไป
(User)		 ประชาชน / บุตรหลาน ค้นหาค่าน้ำด้วยหมายเลขโทรศัพท์หรือบ้านเลขที่ สแกนจ่ายเงิน และแจ้งจุดท่อแตกฉุกเฉิน index.php
2.2 สภาพแวดล้อมและรูปแบบการติดตั้งใช้งาน (Deployment Environment)
รูปแบบที่ 1: ติดตั้งบนเครือข่ายภายใน (Local LAN / On-Premise)
• ติดตั้งแพ็กเกจ XAMPP บนเครื่องคอมพิวเตอร์สำนักงานประปาหมู่บ้าน
• เชื่อมต่อผ่านอุปกรณ์ Wi-Fi Router ภายในที่ทำการ (เช่น 192.168.1.100)
• ไม่ต้องพึ่งพาอินเทอร์เน็ตภายนอก สามารถทำงานได้แม้สัญญาณเน็ตดับ
• เจ้าหน้าที่สำรองฐานข้อมูลเป็นประจำผ่านไฟล์ api/backup.php
รูปแบบที่ 2: ติดตั้งบนเซิร์ฟเวอร์คลาวด์ (Cloud VPS Hosting)
• ติดตั้งบนเซิร์ฟเวอร์เสมือน (Linux/Apache/PHP/MariaDB) พร้อมใบรับรอง SSL
• เข้าใช้งานผ่านโดเมนและเครือข่ายอินเทอร์เน็ตมือถือ 4G/5G ตลอด 24 ชั่วโมง
• ชาวบ้านสามารถตรวจยอดค่าน้ำและสแกนโอนเงินผ่านมือถือได้จากทุกที่
• ช่างจดบันทึกมาตรวัดน้ำสามารถบันทึกข้อมูลเข้าสู่ฐานข้อมูลกลางได้ทันที
ระบบการติดตั้งฐานข้อมูลอัตโนมัติ (Zero-Configuration Database Bootstrap):

3. ข้อกำหนดความต้องการเชิงหน้าที่ (Functional Requirements: FR-01 ถึง FR-05)
FR-01 ระบบทะเบียนผู้ใช้น้ำและการจัดทำสติกเกอร์ QR Code (Customer Registry & QR Labeling)
• คำอธิบาย: จัดเก็บข้อมูลสมาชิกผู้ใช้น้ำ 400 ครัวเรือน กำหนดลำดับเส้นทางเดินจด (seq_no) และจัดพิมพ์สติกเกอร์รหัส QR Code ติดหน้าบ้าน
• ข้อมูลนำเข้า: ชื่อ-สกุล, บ้านเลขที่, โซนจ่ายน้ำ, หมายเลขโทรศัพท์, เลขซีเรียลมิเตอร์, ลำดับเดินจด
• ผลลัพธ์: สร้างรหัสผู้ใช้น้ำ (WY-xxx) และแผ่นพิมพ์สติกเกอร์ QR Code สำหรับติดหน้าบ้าน (12 และ 24 ป้ายต่อแผ่น A4)
• ไฟล์ระบบที่รับผิดชอบ: register.php, print_qr_labels.php, api/customers.php (ตาราง customers)
FR-02 ระบบจดบันทึกเลขอ่านมาตรวัดน้ำภาคสนามตามลำดับเส้นทาง (Sequential Field Recording: ป.17)
• คำอธิบาย: แสดงรายชื่อผู้ใช้น้ำเรียงตามเส้นทางเดินจริง รองรับการสแกน QR Code หน้าบ้านด้วยกล้องมือถือ คำนวณหน่วยใช้ทันที
• ข้อมูลนำเข้า: รอบเดือน/ปี (เช่น 8-2567), รหัสผู้ใช้น้ำ, เลขอ่านมาตรวัดน้ำครั้งนี้
• ผลลัพธ์: บันทึกหน่วยน้ำที่ใช้, ปรับปรุงแถบความคืบหน้าของรอบบิล และแสดงรายชื่อที่ยังไม่ได้จด
• ไฟล์ระบบที่รับผิดชอบ: meter_reading.php, api/readings.php, api/cycles.php (ตาราง meter_readings)
FR-03 ระบบคำนวณค่าน้ำประปาและตรวจจับความผิดปกติอัตโนมัติ (Tariff & Anomaly Engine)
• สูตรการคำนวณ: (จำนวนหน่วยที่ใช้ x 7.00 บาท) + 10.00 บาท (ค่าบำรุง) + หนี้ค้างเก่า = ยอดสุทธิ
• กฎการตรวจจับข้อผิดพลาด: แจ้งเตือนแถบสีแดงกรณี เลขครั้งนี้ < เลขครั้งก่อน (มิเตอร์ย้อนกลับ) หรือใช้น้ำเกิน 3 เท่าของค่าเฉลี่ยเดิม
• ไฟล์ระบบที่รับผิดชอบ: api/readings.php, meter_reading.php
FR-04 ระบบค้นหาและตรวจสอบยอดค่าน้ำสำหรับประชาชน (Public Fast Search Portal)
• คำอธิบาย: ประชาชนพิมพ์หมายเลขโทรศัพท์ 10 หลัก หรือบ้านเลขที่ ระบบค้นหายอดค้างและแสดงปุ่มชำระเงินในเวลาไม่เกิน 0.05 วินาที
• ข้อมูลนำเข้า: หมายเลขโทรศัพท์ / บ้านเลขที่ / รหัสผู้ใช้น้ำ
• ผลลัพธ์: ยอดค่าน้ำปัจจุบัน, ประวัติการใช้น้ำย้อนหลัง, ปุ่มเปิดภาพ QR Code ชำระเงินผ่านพร้อมเพย์
• ไฟล์ระบบที่รับผิดชอบ: index.php, portal_citizen.php, api/customers.php
FR-05 ระบบรับชำระเงินและออกใบเสร็จรับเงินมาตรฐาน (Payment Collection & Receipt: ป.31/32)

• ไฟล์ระบบที่รับผิดชอบ: finance_billing.php (Tab 1-2), api/readings.php, api/receipts.php

5. สถาปัตยกรรมระบบและพจนานุกรมตารางฐานข้อมูล (Architecture & Data Schema)
5.1 สถาปัตยกรรมระบบซอฟต์แวร์ 4 ระดับ (4-Tier Software Architecture)
ระดับชั้น (Tier) เทคโนโลยีและโมดูลที่ใช้ หน้าที่ความรับผิดชอบหลัก
Tier 1: Presentation Responsive Web, Vanilla JS, Bootstrap 5 แสดงผลหน้าจอบนอุปกรณ์ต่างๆ, ระบบค้นหาเบอร์โทร, สแกน QR Code
Tier 2: Application PHP 8 Core, RBAC Session Guard, Business Logic คำนวณค่าน้ำ 7+10 บ., ตรวจจับความผิดปกติ, กรองหนี้ กค.4, ซิงค์ 10%
Tier 3: Data Storage MariaDB 10.4 / MySQL (InnoDB, utf8mb4) จัดเก็บข้อมูลแบบ ACID Transactions, Foreign Keys, Zero-Config DB
Tier 4: Integration PromptPay EMVCo Lib, Excel Export Engine สร้างภาพพร้อมเพย์ตามยอดสตางค์จริง, ส่งออกรายงานเป็นไฟล์ Excel
5.2 พจนานุกรมตารางฐานข้อมูลหลักในระบบ (Core Data Dictionary)
ชื่อตาราง / วิว คีย์หลัก / คีย์นอก (Keys) คำอธิบายและข้อมูลที่จัดเก็บ
tb_customers / customers PK: cus_id (วิวใช้ id) ข้อมูลผู้ใช้น้ำ 400 ครัวเรือน, บ้านเลขที่, โซน, เบอร์โทร, ลำดับเส้นทาง (seq_no)
tb_users PK: user_id | FK: cus_id บัญชีผู้ใช้งานระบบ 4 ระดับ รหัสผ่านเข้ารหัสแบบ BCRYPT ปลอดภัยสูง
billing_cycles PK: id | UK: cycle_code รอบบัญชีค่าน้ำประปาประจำเดือน (เช่น 8-2567), กำหนดวันจดและวันครบกำหนดชำระ
meter_readings PK: id | FK: customer_id, cycle_id เลขอ่านมิเตอร์เดิม-ใหม่, หน่วยน้ำ, ยอดเงิน, สถานะ PAID/UNPAID, เลขที่ใบเสร็จ
payment_vouchers PK: id | FK: billing_cycle_id ใบสำคัญเบิกจ่ายเงินกองทุน, ค่าตอบแทน 10%, ค่าไฟปั๊มน้ำ, ค่าซ่อมท่อแตก
monthly_financial_reports PK: id | FK: billing_cycle_id งบดุลประจำเดือน, รายรับจริง, รายจ่ายจริง, ยอดคงเหลือเงินสดและเงินฝากธนาคาร
service_tickets PK: id | UK: ticket_no รายการแจ้งเหตุน้ำประปาไม่ไหล ท่อแตกรั่ว พร้อมพิกัดและสถานะงานซ่อม
มาตรฐานความมั่นคงปลอดภัยตามแนวทาง OWASP Top 10:
• ใช้คำสั่ง PDO Prepared Statements 100% ทุกไฟล์ ป้องกันการโจมตีแบบ SQL Injection โดยเด็ดขาด
• รหัสผ่านเข้ารหัสทางเดียวด้วย BCRYPT Hashing และมีระบบตรวจสอบ Session สิทธิ์ผู้ใช้งานทุกครั้งก่อนเข้าถึงหน้าการเงิน
