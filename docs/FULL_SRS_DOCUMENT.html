📖 1.2 นิยาม คำศัพท์ และคำย่อ (Definitions & Acronyms)

คำศัพท์/คำย่อ ความหมายเชิงเทคนิคและระเบียบปฏิบัติราชการ

แบบ ป.31/32 ใบแจ้งหนี้ค่าน้ำประปา (ป.31) และใบเสร็จรับเงินค่าน้ำประปาประจำงวด (ป.32) มีผลผูกพันทางกฎหมายการเงิน

👥 2.1 การจำแนกบทบาทและสิทธิ์ผู้ใช้งาน 4 ระดับ (Role Matrix)

บทบาท (Role) กลุ่มผู้ใช้งานจริง สิทธิ์และขอบเขตการปฏิบัติงาน หน้าเริ่มต้น (Landing)
Superadmin ประธานกองทุน / ผู้ใหญ่บ้าน เข้าถึงระบบได้ 100%, อนุมัติฎีกาเบิกจ่าย, ดูงบดุล, แก้ไขอัตราค่าน้ำ, สำรอง DB dashboard.php
Staff เหรัญญิก / ช่างจดมิเตอร์ จดเลขอ่าน ป.17, ตัดรับเงิน, ออกใบเสร็จ ป.31/32, คุมหนี้ กค.4, พิมพ์ QR Code meter_reading.php
Member สมาชิกผู้ใช้น้ำ (ชาวบ้าน) ดูกราฟประวัติใช้น้ำย้อนหลัง, สแกน QR พร้อมเพย์จ่ายเงิน, ส่งเรื่องแจ้งท่อแตก portal_citizen.php
User ประชาชนทั่วไป / บุตรหลาน ค้นหายอดค่าน้ำด้วยเบอร์โทรศัพท์/บ้านเลขที่, สแกนจ่ายพร้อมเพย์, แจ้งเหตุด่วน index.php

🌐 2.2 รูปแบบการติดตั้งใช้งานจริงในชุมชน (Deployment Topology)

โมเดลที่ 1: Local On-Premise LAN (ประหยัดสูงสุด)
• สเปก: ติดตั้ง XAMPP บนคอมพิวเตอร์สำนักงาน 1 เครื่อง (Core i3, RAM 4GB)
• เครือข่าย: เชื่อมต่อผ่าน Wi-Fi Router ภายในที่ทำการ (เช่น 192.168.1.100)
• จุดเด่น: ค่าใช้จ่าย 0 บาท ทำงานได้ 100% แม้อินเทอร์เน็ตชุมชนดับ
• การสำรองข้อมูล: กดสำรองฐานข้อมูลผ่าน api/backup.php ลง Flash Drive ประจำวัน
โมเดลที่ 2: Cloud VPS Hosting (บริการประชาชน 24 ชม.)
• สเปก: รันบน Cloud VPS (Ubuntu 22.04 LTS / Apache / PHP 8 / MariaDB)
• เครือข่าย: ใช้งานผ่านอินเทอร์เน็ต 4G/5G ด้วยโดเมนพร้อมมาตรฐาน SSL (HTTPS)
• จุดเด่น: ชาวบ้านตรวจยอดและโอนจ่ายผ่านมือถือได้ 24 ชั่วโมงจากทุกที่
• ช่างหน้างาน: เดินจดมิเตอร์ตามซอยแล้วข้อมูลซิงค์เข้าเซิร์ฟเวอร์แบบ Real-time
⚡ Zero-Config Database Bootstrap: ระบบมาพร้อมสถาปัตยกรรมสร้างฐานข้อมูลอัตโนมัติ โดยไฟล์ api/db.php จะตรวจสอบว่ามีฐานข้อมูล db_city_water_supply หรือไม่ หากยังไม่มี ระบบจะสร้างและนำเข้าไฟล์ database.sql ให้โดยอัตโนมัติในทันทีที่เริ่มใช้งาน

3. ข้อกำหนดเชิงฟังก์ชัน ตอนที่ 1 (Functional Requirements: FR-01 ถึง FR-05)

Full SRS • ส่วนที่ 3
FR-01: ระบบลงทะเบียนผู้ใช้น้ำ & สติกเกอร์ QR Code (Customer Registry & QR) Priority: High
• คำอธิบาย: บันทึกประวัติผู้ใช้น้ำใหม่ กำหนดลำดับเส้นทางเดินจด (seq_no) และพิมพ์สติกเกอร์ติดหน้าบ้าน
• Inputs: ชื่อ-สกุล, บ้านเลขที่, โซน, เบอร์โทร, เลขซีเรียลมิเตอร์, ลำดับจด | Outputs: รหัส WY-xxx และแผ่นสติกเกอร์ QR
• ไฟล์รับผิดชอบ: register.php, print_qr_labels.php, api/customers.php (ตาราง customers)
FR-02: ระบบเดินจดเลขอ่านมิเตอร์ตามเส้นทางจริง (Sequential Field Recording) Priority: Critical
• คำอธิบาย: แสดงรายชื่อผู้ใช้น้ำเรียงตามเส้นทางเดินจด รองรับการสแกน QR หน้าบ้านด้วยกล้องมือถือ คำนวณหน่วยใช้ทันที
• Inputs: งวดเดือน (เช่น 8-2567), รหัสผู้ใช้น้ำ, เลขอ่านครั้งนี้ | Outputs: จำนวนหน่วยน้ำที่ใช้, แถบความคืบหน้างวด 88%
• ไฟล์รับผิดชอบ: meter_reading.php, api/cycles.php, api/readings.php (ตาราง meter_readings)
FR-03: เอนจินคำนวณค่าน้ำ 7+10 บ. & ตรวจจับผิดปกติ (Tariff & Anomaly Engine) Priority: Critical
• สูตรคำนวณ: (units_used * 7.00 บาท) + 10.00 บาท (ค่าบำรุง) + หนี้ค้างเก่า (Arrears) = ยอดรวมสุทธิ
• กฎตรวจจับ: แจ้งเตือนแถบสีแดงทันทีหาก current < previous (มิเตอร์ย้อนกลับ) หรือใช้น้ำเกิน 3 เท่าของค่าเฉลี่ยเดิม
• ไฟล์รับผิดชอบ: api/readings.php, api/db.php
FR-04: ระบบค้นหายอดค่าน้ำประชาชนด้วยเบอร์โทรศัพท์ (Fast Search Portal) Priority: High
• คำอธิบาย: ประชาชนพิมพ์เพียงเบอร์โทรศัพท์ 10 หลักหรือบ้านเลขที่ ระบบค้นหายอดค้างและแสดงปุ่มชำระเงินทันที
• Inputs: เบอร์โทรศัพท์ / บ้านเลขที่ / รหัสผู้ใช้น้ำ | Outputs: ยอดค่าน้ำ, ประวัติใช้น้ำย้อนหลัง, ปุ่มเปิด QR PromptPay
• ไฟล์รับผิดชอบ: index.php, portal_citizen.php, api/customers.php
FR-05: ระบบตัดรับชำระเงิน & ใบเสร็จ ป.31/32 ทันที (Payment & Receipt Modal) Priority: Critical
• คำอธิบาย: กดปุ่ม [✅ รับชำระ] ตัดยอดเป็น PAID ทันที (Optimistic UI) และกด [🧾 ใบเสร็จ] เปิดพรีวิวใบเสร็จ ป.31/32 สั่งพิมพ์ได้ในคลิกเดียว
• Inputs: customer_id, cycle_id | Outputs: รหัสใบเสร็จ RC-YYYYMM-XXX, ใบเสร็จ ป.31/32 พร้อมตัวอักษรบาทไทย
• ไฟล์รับผิดชอบ: finance_billing.php (Tab 1-2), api/readings.php, api/receipts.php

FR-06: ระบบสร้าง QR Code พร้อมเพย์ตามยอดสุทธิจริง (Dynamic PromptPay QR) Priority: High
• คำอธิบาย: สร้างภาพ QR Code ชำระเงินมาตรฐานธนาคารแห่งประเทศไทย (EMVCo Tag 29/54/58/63) ตรงตามยอดสตางค์จริง
• Inputs: หมายเลขพร้อมเพย์กองทุน, ยอดเงินสุทธิ (เช่น 115.00 บาท) | Outputs: ภาพ QR Code สแกนผ่านทุกแอปธนาคาร
• ไฟล์รับผิดชอบ: index.php, portal_citizen.php, finance_billing.php, api/receipts.php
FR-07: ทะเบียนคุมหนี้ กค.4 & หนังสือเตือนระงับการจ่ายน้ำ (Arrears & Notice) Priority: High
• คำอธิบาย: จัดกลุ่มลูกหนี้ตามอายุหนี้ (1 เดือน, 2 เดือน, 3+ เดือน) พร้อมปุ่มพิมพ์หนังสือเตือนกำหนดชำระ 7 วัน หรือสลับไปตัดเงิน
• การเชื่อมโยง: กดปุ่ม [✉️ เตือน] เปิดพิมพ์หนังสือเตือน / กดปุ่ม [💳 ตัดชำระ] สลับไป Tab 1 พร้อมกรอกชื่อลูกหนี้ให้อัตโนมัติ
• ไฟล์รับผิดชอบ: finance_billing.php (Tab 3: #pane-arrears), api/arrears.php
FR-08: ระบบซิงค์และออกฎีกาเบิกจ่ายค่าตอบแทน 10% (10% Voucher Engine) Priority: Critical
• คำนวณอัตโนมัติ: ยอดค่าตอบแทน 10% = ยอดเงินที่ชำระแล้วในงวดนั้น x 10%
• หมวดค่าใช้จ่ายกองทุน: รองรับ 8 หมวด (ค่าไฟปั๊มน้ำ, ซ่อมท่อ, สารส้ม, ค่าตอบแทน, เบี้ยประชุม) พร้อมแปลงตัวเลขเป็นบาทไทย
• ไฟล์รับผิดชอบ: finance_billing.php (Tab 4: #pane-vouchers), api/vouchers.php (ตาราง payment_vouchers)
FR-09: ระบบงบดุล รายรับ-รายจ่าย & รายงานผู้บริหาร (Executive Reporting) Priority: Medium
• คำอธิบาย: แดชบอร์ดสรุปรายได้จริง หนี้คงค้าง อัตราน้ำสูญเสีย NRW และพิมพ์งบดุลประจำเดือนพร้อมจุดลงนามกรรมการ 3 ท่าน
• การส่งออก: ส่งออกตารางการใช้น้ำและบัญชีเป็นไฟล์ Excel ผ่าน api/export_excel.php
• ไฟล์รับผิดชอบ: dashboard.php, executive_reports.php, api/financials.php
FR-10: ระบบรับแจ้งท่อแตก-น้ำรั่ว & ติดตามงานซ่อม (Service Ticket Tracking) Priority: Medium
• คำอธิบาย: ประชาชนส่งเรื่องแจ้งท่อแตก น้ำไม่ไหล พร้อมระบุพิกัด และเจ้าหน้าที่อัปเดตสถานะงานซ่อมจนแล้วเสร็จ
• ไฟล์รับผิดชอบ: index.php, portal_citizen.php, dashboard.php, api/tickets.php (ตาราง service_tickets)

🏗️ สถาปัตยกรรมระบบ 4 ระดับ (4-Tier Software Architecture)

ระดับชั้น (Tier) เทคโนโลยีและโมดูล (Components) หน้าที่ความรับผิดชอบหลัก
Tier 1: Presentation Responsive Web UI, Vanilla JS, Bootstrap 5 แสดงผลหน้าจอมือถือ/คอมพิวเตอร์, ระบบค้นหาเบอร์โทร, สแกน QR Code
Tier 2: Application PHP 8 Core, RBAC Gatekeeper, Business Engines คำนวณค่าน้ำ 7+10 บ., ตรวจจับความผิดปกติ, กรองหนี้ กค.4, ซิงค์ 10%
Tier 3: Data Storage MariaDB 10.4 / MySQL (InnoDB Engine, utf8mb4) ธุรกรรม ACID, Foreign Keys, Zero-Config Bootstrap, 1-Click Backup
Tier 4: Integration PromptPay EMVCo Lib, Excel Exporter สร้าง Payload พร้อมเพย์ตรงสตางค์, ส่งออกสถิติค่าน้ำเป็นไฟล์ Excel

🗄️ พจนานุกรมตารางฐานข้อมูลหลัก (Core Data Dictionary)

ชื่อตาราง (Table Name) คีย์หลัก / คีย์นอก (Keys) คำอธิบายและข้อมูลที่จัดเก็บ
customers PK: id | UK: customer_code ข้อมูลสมาชิกผู้ใช้น้ำ 400 ครัวเรือน, บ้านเลขที่, โซน, เบอร์โทร, seq_no
billing_cycles PK: id | UK: cycle_code รอบเดือน/ปีบัญชีค่าน้ำประปา เช่น 8-2567 (สิงหาคม 2567)
meter_readings PK: id | FK: customer_id, cycle_id ประวัติเลขอ่านมิเตอร์เดิม-ใหม่, หน่วยน้ำ, ยอดเงิน, สถานะ PAID/UNPAID
payment_vouchers PK: id | FK: cycle_id ฎีกาเบิกจ่ายกองทุน, ค่าตอบแทน 10%, ค่าไฟปั๊มน้ำ, ค่าซ่อมท่อแตก
monthly_financial_reports PK: id | FK: cycle_id งบดุลประจำเดือน, รายรับจริง, รายจ่ายจริง, ยอดคงเหลือ, น้ำสูญเสีย NRW
service_tickets PK: id | FK: customer_id รับแจ้งเหตุท่อแตก, น้ำประปาไม่ไหล, สถานะการเข้าซ่อมแซม
🛡️ ความปลอดภัยตามมาตรฐาน OWASP Top 10:
• ป้องกัน SQL Injection 100% ด้วยการใช้ PDO Prepared Statements ทุกคำสั่ง
• เข้ารหัสผ่านด้วย BCRYPT Hashing ทางเดียว ป้องกันรหัสผ่านรั่วไหลจากฐานข้อมูล
• มีระบบ Gatekeeper Session Guard คอยตรวจสิทธิ์ผู้ใช้ก่อนอนุญาตให้เข้าหน้าการเงิน
