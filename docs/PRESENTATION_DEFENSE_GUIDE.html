1. สคริปต์บทพูดนำเสนออย่างละเอียด (สไลด์ที่ 1 - 3)

Defense Guide • ส่วนที่ 2
🎙️ สไลด์ที่ 1: แนะนำตัว ที่มา และสภาพปัญหาดั้งเดิม (Opening & Problem Statement)
"กราบเรียนท่านอาจารย์และคณะกรรมการทุกท่านครับ วันนี้พวกเราขอนำเสนอ ระบบบริการและบริหารจัดการน้ำประปาหมู่บ้านอัจฉริยะ การประปาหมู่บ้านวังยาง ครับ
แรงบันดาลใจของโครงการนี้เกิดจากสภาพปัญหาจริงของกิจการประปาชนบท 400 ครัวเรือนในหมู่ที่ 3 ตำบลวังยาง ซึ่งยังคงใช้ระบบจดบันทึกด้วยสมุดกระดาษและไฟล์ Excel ทำให้เกิดปัญหาคลาสสิก 4 ประการครับ: (1) การจดเลขมิเตอร์ตกหล่นและตัวเลขย้อนกลับ (2) การออกบิลล่าช้า ชาวบ้านไม่ทราบยอดจนเกิดหนี้สะสมเรื้อรัง (3) ความยุ่งยากในการหักค่าตอบแทนผู้จัดเก็บ 10% ที่ขาดเอกสารใบสำคัญรับเงิน และ (4) ความเสี่ยงข้อมูลสูญหายหากคอมพิวเตอร์สำนักงานเกิดความเสียหายครับ พวกเราจึงได้พัฒนาระบบนี้ขึ้นมาเพื่อปฏิรูปกระบวนการทั้งหมดให้เป็นดิจิทัล 100% ตั้งแต่หน้าบ้านจนถึงการทำบัญชีงบดุลของกองทุนครับ"
🎙️ สไลด์ที่ 2: สถาปัตยกรรมระบบ 4-Tier และความพร้อมใช้งานจริง (Architecture & Deployment)
"ในเชิงวิศวกรรมซอฟต์แวร์ เราออกแบบระบบนี้ภายใต้ 4-Tier Enterprise Architecture อย่างเป็นทางการครับ:
• Tier 1 (Presentation): Responsive Web UI รองรับทั้งคอมพิวเตอร์และมือถือ ค้นหาเร็วด้วยเบอร์โทรศัพท์ และสแกนกล้อง QR Code หน้าบ้าน
• Tier 2 (Application Logic): ประมวลผลด้วย PHP 8 Core มีเอนจินคำนวณค่าน้ำ 7+10 บาท, เอนจินตรวจจับตัวเลขผิดปกติ, เอนจินแปลงบาทไทย, และเอนจินซิงค์ค่าตอบแทน 10%
• Tier 3 (Data Persistence): ฐานข้อมูล MariaDB/MySQL Engine แบบ InnoDB รองรับธุรกรรม ACID 100%
• Tier 4 (Integration): เชื่อมต่อ QR พร้อมเพย์มาตรฐาน EMVCo และระบบส่งออก Excel ครับ
ที่สำคัญ ระบบนี้รองรับสภาพแวดล้อมจริงได้ 2 รูปแบบ คือจะติดตั้งบนคอมพิวเตอร์สำนักงานแบบ Local On-Premise LAN เพื่อทำงานแบบออฟไลน์ 100% โดยไม่มีค่าใช้จ่าย หรือจะขึ้น Cloud VPS ราคาประหยัดเพื่อให้ชาวบ้านตรวจค่าน้ำได้ 24 ชั่วโมงก็ได้ครับ พร้อมระบบ Zero-Config ที่สร้างฐานข้อมูลอัตโนมัติเมื่อเปิดครั้งแรกครับ"
🎙️ สไลด์ที่ 3: วงจรการทำงานหน้างานและการบริการประชาชน (Field & Citizen Workflow)
"ในขั้นตอนการปฏิบัติงานหน้างาน เจ้าหน้าที่ใช้สมาร์ตโฟนเปิดหน้า meter_reading.php เพื่อเดินจดมิเตอร์ตามเส้นทางจริง (seq_no) หรือใช้กล้องสแกนสติกเกอร์ QR Code ที่เราพิมพ์ไปติดไว้ที่หน้าบ้านผ่านหน้า print_qr_labels.php ครับ
เมื่อกรอกเลขอ่านครั้งนี้ ระบบจะคำนวณหน่วยใช้และยอดเงินทันที หากกรอกตัวเลขน้อยกว่าครั้งก่อน ระบบจะล็อกแถบสีแดงแจ้งเตือนทันทีครับ
และในฝั่งของประชาชน สามารถเข้าหน้า index.php เพื่อตรวจสอบยอดค่าน้ำของบ้านตนเองได้ง่ายๆ เพียงพิมพ์หมายเลขโทรศัพท์ 10 หลัก ระบบจะดึงยอดค้างชำระ พร้อมสร้างภาพ QR Code พร้อมเพย์มาตรฐานธนาคารแห่งประเทศไทยที่ระบุยอดเงินตรงตามสตางค์ให้ชาวบ้านสแกนจ่ายได้ทันทีครับ"

🎙️ สไลด์ที่ 4: ระบบการเงินแบบบูรณาการ ใบเสร็จ ป.31/32 และหนี้ กค.4 (Unified Finance & Governance)
"หัวใจสำคัญของระบบการเงินอยู่ที่หน้า finance_billing.php ครับ เราออกแบบให้เป็น Unified Control Header รวม 4 ระบบงานไว้ในหน้าเดียว:
1. เมื่อชาวบ้านมาชำระเงิน เหรัญญิกกดปุ่ม [รับชำระ] ระบบจะตัดยอดเป็น PAID แบบ Optimistic UI ทันที และมีปุ่ม [ใบเสร็จ] ให้เปิดพรีวิวและพิมพ์ใบเสร็จรับเงินมาตรฐาน ป.31/32 ได้ในเสี้ยววินาทีโดยไม่ต้องสลับหน้าจอ
2. ในส่วนของหนี้ค้างชำระ มีทะเบียนคุมหนี้ตามแบบ กค.4 จัดกลุ่ม 1, 2, 3+ เดือน พร้อมปุ่มพิมพ์หนังสือเตือนระงับการจ่ายน้ำกำหนด 7 วันได้ทันที
3. ในส่วนเงินรายได้ ระบบสามารถกดปุ่ม [ซิงค์ค่าตอบแทน 10%] เพื่อคำนวณเงินรางวัลคนเก็บจากยอดรับจริงในงวดนั้น พร้อมออกฎีกาเบิกจ่ายเงินที่มีช่องลงนาม 3 ท่านอย่างถูกต้องตามระเบียบราชการครับ"
🎙️ สไลด์ที่ 5: การเชื่อมโยงจากต้นแบบ Axure RP สู่โค้ดระบบจริง (Prototype Traceability)
"ก่อนการพัฒนาโค้ดจริง เราได้จัดทำภาพร่างต้นแบบอย่างละเอียดใน Axure RP (ไฟล์ Plumber_ver-1003-gu-tam-kon-dew-i-sus.rp) ครบทั้ง 31 หน้าจอ โดยโครงสร้าง UI ทุกองค์ประกอบในไฟล์ต้นแบบ ได้รับการพัฒนาเป็นโค้ดระบบจริงครบถ้วน 100% ไม่ว่าจะเป็นหน้าค้นหาประชาชน, หน้าจดมิเตอร์ ป.17, หน้าใบเสร็จ ป.31/32, หน้าฎีกาเบิกจ่าย 10%, หน้างบดุลการเงิน และระบบพิมพ์สติกเกอร์ QR Code ครับ"
🎙️ สไลด์ที่ 6: บทสรุปและความพร้อมในการส่งมอบ (Conclusion & Deliverables)

2. คลังคำถาม-คำตอบปราบเซียนจากคณะกรรมการ (Q&A Defense ตอนที่ 1)

Defense Guide • ส่วนที่ 3
❓ คำถามที่ 1: ทำไมกลุ่มคุณถึงเลือกใช้ PHP Native แทนที่จะใช้ Modern Framework เช่น Laravel หรือ React?
💡 แนวทางการตอบ: "เป็นคำถามที่ตรงจุดมากครับ เหตุผลหลักคือ **สภาพแวดล้อมจริงของสำนักงานประปาหมู่บ้านชนบท (Target Operational Environment)** ครับ:
1. คอมพิวเตอร์ที่ทำการหมู่บ้านเป็นเครื่องสเปกพื้นฐาน (Core i3, RAM 4GB) และผู้ดูแลคือผู้ใหญ่บ้านหรือเหรัญญิก ไม่ใช่ Software Engineer หากใช้ Laravel หรือ Node.js การติดตั้งจะต้องพึ่งพา composer, npm build, Docker และต้องต่อเน็ตความเร็วสูงในการอัปเดต ซึ่งไม่เหมาะกับบริบทชุมชน
2. การใช้ PHP 8 Native ร่วมกับ Vanilla JS ทำให้ระบบมีขนาดเบามาก (Low Overhead), โหลดเร็วในเวลาต่ำกว่า 0.2 วินาที, รันผ่าน XAMPP ได้ทันทีโดยไม่ต้องตั้งค่าเพิ่มเติม (Zero-Config), และสามารถทำงานแบบ Offline 100% ได้อย่างเสถียรที่สุดครับ"
❓ คำถามที่ 2: ถ้าเกิดเหตุไฟดับหรือระบบขัดข้องขณะกำลังบันทึกข้อมูลการเงิน ข้อมูลจะสูญหายหรือเสียหายหรือไม่?
💡 แนวทางการตอบ: "ระบบของเราป้องกันปัญหานี้ไว้ 2 ชั้นครับ:
1. ชั้นฐานข้อมูล: เราใช้ MariaDB/MySQL Storage Engine แบบ **InnoDB** ซึ่งรองรับคุณสมบัติ **ACID (Atomicity, Consistency, Isolation, Durability)** การทำธุรกรรมการเงินทุกจุดจะทำงานอยู่ภายใต้ Database Transaction หากระบบดับกลางคัน ข้อมูลจะถูก Rollback อัตโนมัติ ไม่เกิดภาวะข้อมูลค้างคาหรือตัดยอดซ้ำ
2. ชั้น Disaster Recovery: เรามีเอนจิน `api/backup.php` ที่ให้เหรัญญิกกดสำรองฐานข้อมูลออกมาเป็นไฟล์ `.sql` ลง Flash Drive ได้ในคลิกเดียวทุกวัน ทำให้สามารถกู้คืนระบบกลับมาได้ภายใน 5 นาที (RTO < 5 นาที) ครับ"
❓ คำถามที่ 3: ระบบป้องกันปัญหาการปลอมแปลงสลิป หรือการแอบแก้ไขยอดเงินค่าน้ำอย่างไร?
💡 แนวทางการตอบ: "เราใช้มาตรการควบคุมความปลอดภัย 3 ด้านครับ:
1. การใช้ **Role-Based Access Control (RBAC)**: สมาชิกและประชาชนทั่วไปมีสิทธิ์เพียงแค่เรียกดู (Read-Only) เท่านั้น ไม่มีสิทธิ์ส่งคำสั่งอัปเดตสถานะชำระเงิน
2. การใช้ **PDO Prepared Statements 100%**: ทุกคำสั่ง SQL มีการผูกตัวแปร Parameter Binding ป้องกันการยิง SQL Injection เพื่อลักลอบแก้ข้อมูล
3. ระบบ **Audit Trail & Receipt Numbering**: การตัดชำระเงินทุกครั้งจะบันทึกเวลา `paid_at = NOW()` และออกเลขที่ใบเสร็จ `RC-YYYYMM-XXX` ที่รันต่อเนื่องกันแบบผูกพันทางบัญชี ทำให้สามารถตรวจสอบย้อนหลังได้เสมอครับ"
❓ คำถามที่ 4: ทำไมระบบถึงมี 'ฎีกาเบิกจ่าย 10%' สิ่งนี้จำเป็นอย่างไรในระบบประปาหมู่บ้าน?
💡 แนวทางการตอบ: "การมีฎีกา 10% คือสิ่งที่ทำให้ระบบนี้ **สอดคล้องกับระเบียบการบริหารกิจการประปาหมู่บ้านของกระทรวงมหาดไทย** อย่างแท้จริงครับ:
ในทางปฏิบัติ ผู้จัดเก็บค่าน้ำคือชาวบ้านที่ต้องเดินเท้าตามซอยเพื่อเก็บเงิน ระเบียบกองทุนจึงกำหนดให้มีเงินรางวัลการจัดเก็บอัตราร้อยละ 10 จาก 'ยอดเงินที่จัดเก็บได้จริง'
ในระบบเดิม เหรัญญิกต้องมานั่งกดเครื่องคิดเลขและหักเงินสดกันเองโดยไม่มีเอกสาร ทำให้เกิดข้อพิพาทความไม่โปร่งใส ระบบของเราจึงสร้างเอนจินคำนวณยอด 10% จากบิลที่ชำระแล้วโดยอัตโนมัติ และพิมพ์ใบสำคัญรับเงินที่มีลายมือชื่อ 3 ฝ่าย (ผู้รับเงิน, เหรัญญิก, ประธานกองทุน) ทำให้เกิดธรรมาภิบาลและความโปร่งใสครับ"

2. **QR Code พร้อมเพย์:** เป็น **EMVCo Payment Payload** ที่เข้ารหัสบัญชีกองทุนและยอดเงินสตางค์ตามมาตรฐานธนาคารแห่งประเทศไทย สำหรับให้ชาวบ้านใช้แอปธนาคารสแกนโอนเงินจ่ายค่าน้ำครับ"
