ข้อที่ 1: การอธิบายระบบจากโครงงานกลุ่ม (10 คะแนน)

หัวใจในการตรวจ: กรรมการมองหา "ความเป็นระบบและความละเอียด" ห้ามตอบสั้นเป็นความเรียงก้อนเดียว ให้เขียนเป็นข้อๆ พร้อมระบุขั้นตอน Input $\rightarrow$ Process $\rightarrow$ Output

1.1 ข้อมูลระบบและวัตถุประสงค์ (System Overview & Objectives)

  • ชื่อระบบ: ระบบบริหารจัดการการประปาหมู่บ้านวังยาง (Village Water Supply Management System)
  • เทคโนโลยีที่ใช้: PHP + MySQL (MariaDB) บนสภาพแวดล้อม XAMPP สถาปัตยกรรม Web-based Client-Server
  • สภาพปัญหาก่อนพัฒนา: เดิมเจ้าหน้าที่ใช้สมุดกระดาษจดเลขมิเตอร์ (ป.17) ทำให้ตัวเลขคลาดเคลื่อนง่าย, คำนวณค่าน้ำและทบยอดหนี้ค้างชำระผิดพลาด, ประชาชนไม่ทราบยอดค่าน้ำล่วงหน้า, และสรุปบัญชีการเงินชุมชนล่าช้า
  • วัตถุประสงค์หลัก:
    1. เปลี่ยนระบบจดและคำนวณค่าน้ำประปาเป็นดิจิทัล ลดความผิดพลาดและทบยอดหนี้ค้างชำระอัตโนมัติ
    2. พัฒนาระบบตรวจสอบค่าน้ำ แจ้งชำระเงิน และยื่นคำร้องแจ้งซ่อมท่อรั่วออนไลน์สำหรับประชาชน
    3. จัดทำระบบรายงานสรุปงบการเงิน รายรับ-รายจ่าย รายการหนี้ค้างชำระ และอัตราน้ำสูญเสีย (NRW) ประจำเดือน

บทบาท (Role) โมดูลที่รับผิดชอบ หน้าที่และการทำงานหลัก
1. ผู้ดูแลระบบ (Admin) dashboard.php
executive_reports.php		 บริหารจัดการระบบทั้งหมด กำหนดอัตราค่าน้ำต่อหน่วย ดูรายงานรายรับ-รายจ่าย และสถิติน้ำสูญเสีย
2. เจ้าหน้าที่ (Staff) meter_reading.php
finance_billing.php		 บันทึกเลขมิเตอร์ประจำงวด ตัดรับชำระเงิน ออกใบเสร็จมาตรฐาน และจัดทำฎีกาเบิกจ่ายเงินกองทุน
3. สมาชิกผู้ใช้น้ำ (Member) portal_citizen.php เข้าสู่ระบบด้วยรหัสผู้ใช้น้ำ ดูประวัติการใช้น้ำย้อนหลัง พิมพ์ใบเสร็จ และสแกน QR Code ชำระเงิน

1.3 ขั้นตอนการทำงานอย่างละเอียด: Input $\rightarrow$ Process $\rightarrow$ Output (จุดเน้นข้อสอบ!)

ให้อธิบายอย่างน้อย 2 ฟังก์ชันหลักของระบบ ดังนี้:

ฟังก์ชันที่ 1: ระบบสมุดจดบันทึกเลขมิเตอร์และคำนวณค่าน้ำอัตโนมัติ (Meter Reading & Billing)
1. ข้อมูลนำเข้า (Input) • รหัสรอบบิล (เช่น ส.ค. 2567)
• รหัสผู้ใช้น้ำ (customer_id)
• เลขมิเตอร์ครั้งนี้ (current_reading)
➔
2. การประมวลผล (Process) • ตรวจสอบเลขมิเตอร์ปัจจุบัน $\ge$ เลขครั้งก่อน
• หน่วยใช้ = เลขครั้งนี้ − เลขครั้งก่อน
• ค่าน้ำ = หน่วยใช้ $\times$ อัตราต่อหน่วย (7 บาท)
• ยอดสุทธิ = ค่าน้ำ + ค่าบริการ (10) + หนี้เก่า
➔
3. การแสดงผล (Output) • รายการบันทึกสถานะ UNPAID
• ยอดรวมค่าน้ำสุทธิบนหน้าจอ
• ใบแจ้งหนี้ค่าน้ำประจำงวด
• บันทึกลงตาราง meter_readings
ฟังก์ชันที่ 2: ระบบตัดรับชำระเงินและออกใบเสร็จรับเงิน (Finance & Receipts)
1. ข้อมูลนำเข้า (Input) • เลขที่บิล / รหัสผู้ใช้น้ำ
• จำนวนเงินรับชำระ (amount_paid)
• ช่องทาง (เงินสด / PromptPay)
➔
2. การประมวลผล (Process) • ตรวจสอบยอดเงินครบถ้วน
• อัปเดตสถานะบิลเป็น 'PAID'
• ออกเลขที่ใบเสร็จ (เช่น 8-2567/501)
• แปลงยอดเงินเป็นตัวอักษรไทย (bahtText)
➔
3. การแสดงผล (Output) • ใบเสร็จรับเงินทางการพร้อมพิมพ์
• ปรับลดยอดหนี้คงเหลือเป็น 0.00
• ปรับปรุงยอดรายรับรวมในแดชบอร์ด

1.4 ส่วนงานที่ตนเองรับผิดชอบ (Role & Contribution — เขียนตอบให้ดูเป็นมืออาชีพ)

(เลือกตอบด้านใดด้านหนึ่งที่ตนเองมั่นใจ):

  • แนวตอบด้านฐานข้อมูลและแบ็กเอนด์ (Backend & Database Developer):
    "ข้าพเจ้ารับผิดชอบการออกแบบฐานข้อมูลเชิงสัมพันธ์ (Database Schema) ตาราง tb_customers, meter_readings, billing_cycles, tb_users พร้อมกำหนด Primary Key, Foreign Key และ Referential Integrity เพื่อป้องกันข้อมูลขัดแย้ง รวมถึงเขียนคำสั่ง SQL และสคริปต์ PHP ฝั่งเซิร์ฟเวอร์ในการประมวลผลคำนวณค่าน้ำแบบอัตโนมัติ จัดการระบบ Session Login ป้องกันการเข้าถึงโดยไม่ได้รับอนุญาต และสร้าง API สำหรับออกใบเสร็จรับเงิน"
  • แนวตอบด้านส่วนติดต่อผู้ใช้ (Frontend & UI Developer):
    "ข้าพเจ้ารับผิดชอบการออกแบบหน้าจอผู้ใช้งาน (UI/UX) ให้ทำงานแบบ Responsive Web รองรับแท็บเล็ตและสมาร์ตโฟนสำหรับเจ้าหน้าที่จดมิเตอร์ภาคสนาม พัฒนาระบบตรวจสอบความถูกต้องของข้อมูล (Form Validation) ด้วย JavaScript เพื่อป้องกันไม่ให้กรอกเลขมิเตอร์ติดลบหรือน้อยกว่าครั้งก่อนหน้า และพัฒนาหน้า Portal ให้ประชาชนสแกน QR Code ชำระเงินได้อย่างสะดวก"

ข้อที่ 2: การเขียนคำสั่ง SQL (10 คะแนน — 5 ข้อย่อย)

แนวข้อสอบ: มีตารางและคอลัมน์กำหนดมาให้ ให้นักศึกษาเขียนคำสั่ง SELECT ตอบให้ตรงตามเงื่อนไขที่โจทย์ต้องการ

โครงสร้างตารางจำลองสำหรับข้อสอบ

เก็งโจทย์ 5 ข้อย่อย พร้อมเฉลยละเอียดและหลักการคิด

ข้อย่อยที่ 1: การเลือกคอลัมน์ (SELECT) และการเปรียบเทียบตัวเลข (WHERE > หรือ <) 2 คะแนน

โจทย์: จงเขียนคำสั่ง SQL เพื่อแสดงรหัสพนักงาน (emp_id), ชื่อพนักงาน (emp_name) และเงินเดือน (salary) ของพนักงานที่มีเงินเดือนมากกว่า 35,000 บาท

SELECT emp_id, emp_name, salary
FROM employees
WHERE salary > 35000;
💡 ข้อสังเกต: ตัวเลขไม่ต้องใส่เครื่องหมายคำพูด (Quote)
ข้อย่อยที่ 2: การกำหนดหลายเงื่อนไขด้วย AND และ OR (ระวังใส่วงเล็บ) 2 คะแนน

โจทย์: จงแสดงชื่อพนักงาน แผนก และเงินเดือน ของพนักงานที่อยู่แผนก 'ไอที' หรือ 'การเงิน' และมีเงินเดือนตั้งแต่ 30,000 บาทขึ้นไป

SELECT emp_name, department, salary
FROM employees
WHERE (department = 'ไอที' OR department = 'การเงิน')
  AND salary >= 30000;
⚠️ จุดหักคะแนน: หากไม่ใส่วงเล็บรอบกลุ่ม OR ลำดับการประมวลผลจะเอา AND ทำก่อน ทำให้คนแผนกไอทีเงินเดือนเท่าไรก็โผล่มาทันที!
ข้อย่อยที่ 3: การคำนวณระยะเวลาหรืออายุงานจากปีที่โจทย์กำหนด 2 คะแนน

โจทย์: จงแสดงชื่อพนักงาน วันที่เริ่มงาน และอายุงาน (จำนวนปี) จนถึงปี 2024 พร้อมแสดงเฉพาะผู้ที่มีอายุงานมากกว่า 5 ปี

SELECT emp_name, hire_date, (2024 - YEAR(hire_date)) AS work_years
FROM employees
WHERE (2024 - YEAR(hire_date)) > 5;
💡 กรณีโจทย์ให้เทียบกับปีปัจจุบันของระบบ: ให้เปลี่ยน 2024 เป็น YEAR(CURDATE()) เช่น (YEAR(CURDATE()) - YEAR(hire_date))
ข้อย่อยที่ 4: การกรองข้อมูลตามข้อความ (สถานที่ และประเภทค่าใช้จ่าย) 2 คะแนน

โจทย์: จงแสดงรายการค่าใช้จ่ายทั้งหมดที่เป็นประเภท 'ค่าซ่อมบำรุง' หรือ 'ค่าเดินทาง' ที่เกิดขึ้น ณ สถานที่ 'เชียงใหม่'

SELECT *
FROM expenses
WHERE (exp_type = 'ค่าซ่อมบำรุง' OR exp_type = 'ค่าเดินทาง')
  AND location = 'เชียงใหม่';
💡 อีกวิธีที่ถูกต้อง: ใช้ IN แทนได้: WHERE exp_type IN ('ค่าซ่อมบำรุง', 'ค่าเดินทาง') AND location = 'เชียงใหม่'
ข้อย่อยที่ 5: การอ่านโครงสร้างตาราง และการกรองด้วย LIKE / NOT EQUAL 2 คะแนน

โจทย์: จงแสดงรหัสค่าใช้จ่าย จำนวนเงิน และสถานที่ ของรายการที่มีจำนวนเงินตั้งแต่ 5,000 บาทขึ้นไป และสถานที่ไม่ใช่ 'กรุงเทพ'

SELECT exp_id, amount, location
FROM expenses
WHERE amount >= 5000
  AND location <> 'กรุงเทพ';
💡 เครื่องหมายไม่เท่ากับใน SQL เขียนได้ทั้ง <> หรือ !=
